# Школа таджвида Djawda

Сайт женской школы таджвида «Джавда» — одна страница, которую можно отправить ученице: курсы, форматы, цены, сроки, запись, вопросы, преподаватели и контакты. Тексты и картинки правятся в Keystatic (`/keystatic`) без правки вёрстки.

Прод предполагается на Vercel: [djawda.vercel.app](https://djawda.vercel.app).

## Локальный запуск

Нужны Node.js 20+ и npm.

```bash
npm install
cp .env.example .env.local
npm run dev
```

Сайт: http://127.0.0.1:3000  
Админка: http://127.0.0.1:3000/keystatic

В режиме разработки Keystatic пишет прямо в файлы `content/` и `public/`. После правки обновите страницу сайта: в dev подключён авто-рефреш ридера.

Проверки:

```bash
npm run lint
npx tsc --noEmit
npm run format:check
npm run build
```

## Как устроен код

Одна страница `/` собирается на сервере: `app/(site)/page.tsx` один раз читает Keystatic и раскладывает блоки из `components/sections`. Шапка и подвал живут в макете группы `(site)` и не оборачивают `/keystatic`. Интерактивные куски — клиентские острова в `components/ui` (раскрытие курса, форма, FAQ, шёлк, шкала разделов).

`lib/cms` — единственное чтение контента. `lib/forms` — схема заявки на zod (её же проверяют форма и `POST /api/lead`), телефон и лимит. `lib/integrations` — Google Sheets и Telegram; если ключей нет, заявка не падает. Переменные окружения разбираются в `lib/env.ts`. Секретов в коде нет.

Первый экран — спокойный шёлковый фон на одном шейдере WebGL: тёмно-серые складки и мелкое зерно. Формула взята из [Silk Background Animation](https://21st.dev/@waleedkibhen/components/silk-background-animation) (vvisedev Crafts на [21st.dev](https://21st.dev)) и перенесена на GPU. Реестр shadcn для этого компонента просит ключ 21st, поэтому исходник адаптирован в `components/ui/silk-background.tsx`. Слой встаёт на паузу вне экрана. При `prefers-reduced-motion` остаётся один статичный кадр. Заголовок — светлый Cormorant, без блика. Плавная прокрутка — Lenis. Справа тонкая вертикальная шкала разделов: линия заполняется сверху вниз, кружок раздела загорается, когда до него доскроллили, нажатие ведёт к якорю. Шаги подхода — обычные карточки. Остальная анимация — Motion. Картинки идут через `next/image`. Заголовки — Cormorant, текст — Manrope, оба через `next/font` с кириллицей.

Палитра чередует почти чёрные и почти белые блоки. Шёлк, подход, направления, формат, контакты и подвал остаются `#0f0f10`. Бегущая строка, «кому подойдёт», преподаватели, вопросы и заявка — `#f5f5f4` и `#ececea` с тёмным текстом. Списки курса и формата в заявке — своё меню, не системный лист телефона.

## Редактирование в Keystatic

Админка на русском (`locale: ru-RU`).

### Локально

Ничего подключать не нужно. `npm run dev` → `/keystatic`. Режим хранения — `local`: сохранение сразу меняет файлы в репозитории. Их нужно закоммитить и запушить, иначе на проде останется старый текст.

Принудительно:

```bash
KEYSTATIC_STORAGE=local
NEXT_PUBLIC_KEYSTATIC_STORAGE=local
```

Обе переменные должны совпадать. `NEXT_PUBLIC_` видна браузерной части админки.

### GitHub-режим на проде

На Vercel правки не пишутся на диск сервера. Keystatic коммитит в репозиторий `salmanbahaev/djawda`, Vercel пересобирает сайт.

Если переменные хранения не заданы, в `npm run dev` берётся `local`. При production-сборке берётся `github`, но только когда уже заданы `KEYSTATIC_GITHUB_CLIENT_ID`, `KEYSTATIC_GITHUB_CLIENT_SECRET` и `KEYSTATIC_SECRET`. Без этих ключей сборка остаётся в `local`, иначе Keystatic останавливает `next build`. На Vercel после добавления ключей следующая сборка сама включит GitHub-режим. Явный `KEYSTATIC_STORAGE=github` тоже включает его и тогда ключи обязательны.

### Как создать GitHub App

1. Откройте [GitHub → Settings → Developer settings → GitHub Apps → New GitHub App](https://github.com/settings/apps/new).
2. Название, например `Djawda Keystatic`.
3. Homepage URL: `https://djawda.vercel.app`.
4. Callback URL: `https://djawda.vercel.app/api/keystatic/github/oauth/callback`.
5. Снимите галочку Webhook → Active.
6. Права репозитория:
   - Contents: Read and write
   - Pull requests: Read and write
   - Metadata: Read-only (обычно уже стоит)
7. «Where can this GitHub App be installed?» — Only on this account.
8. Создайте приложение, сгенерируйте client secret.
9. Установите приложение на репозиторий `salmanbahaev/djawda`.
10. Слаг приложения — это кусок адреса `https://github.com/apps/ВАШ-СЛАГ`.

Секрет сессии:

```bash
openssl rand -base64 32
```

Положите в переменные Vercel (и пересоберите проект, потому что `NEXT_PUBLIC_` попадает в сборку):

| Переменная                              | Где              |
| --------------------------------------- | ---------------- |
| `KEYSTATIC_STORAGE=github`              | сервер           |
| `NEXT_PUBLIC_KEYSTATIC_STORAGE=github`  | сборка и браузер |
| `KEYSTATIC_GITHUB_CLIENT_ID`            | сервер           |
| `KEYSTATIC_GITHUB_CLIENT_SECRET`        | сервер           |
| `KEYSTATIC_SECRET`                      | сервер           |
| `NEXT_PUBLIC_KEYSTATIC_GITHUB_APP_SLUG` | сборка и браузер |

Дальше на проде открывается `https://djawda.vercel.app/keystatic`, GitHub спрашивает доступ, правка уходит коммитом в репозиторий.

## Админка: что можно менять

Одиночные записи:

- **Настройки сайта** — знак, словесные знаки Djawda / «Школа таджвида», телефон, WhatsApp, Telegram, Instagram, адрес, карта, пункты меню (якоря `#approach`, `#courses` и остальные), SEO по умолчанию.
- **Главная** — первый экран, подход, «кому подойдёт», каталог, подписи кнопок карточки курса, форматы, шаги записи, FAQ, блок контактов, финальный призыв.
- **О школе** — текст школы и преподаватели (только текст). Отдельной страницы нет: блок стоит на главной перед карточками преподавателей.
- **Страница контактов** — запись в админке сохранена. На сайте контакты, карта и форма берутся из «Главной» и настроек.
- **Форма заявки** — подписи полей, три формата, согласие, тексты успеха и ошибки.
- **Подвал**
- **Политика** — сейчас заглушка.

Коллекция **Курсы**: добавить, изменить, удалить. Карточки на главной и список в форме собираются из этой коллекции. Отдельных страниц курсов нет: карточка раскрывается на месте. Прямая ссылка — якорь `#course-` и slug, например `#course-tashih`.

Поля курса: название, якорь (slug), краткое описание, подзаголовок, форматы, длительность, размер группы (можно пустым), стоимость текстом, статус набора, порядок, картинка карточки, картинка материалов, разделы карточки, FAQ, SEO. SEO курса в шапку сайта не выводится: у страницы один заголовок и одно описание.

Статус набора — выбор:

- `open` — «Идёт набор»
- `soon` — «Скоро набор»

Сейчас у всех курсов стоит «Скоро набор»: в ТЗ не сказано, какой набор открыт. Поменять можно в карточке курса. Новый статус: дописать объект в `lib/course-status.ts`, задеплоить — пункт появится в списке.

У вопросов FAQ есть галочка **Черновик**. Она видна только в админке. На сайте ответ всё равно показывается: вопросы взяты из ТЗ, формулировки ответов собраны по тексту ТЗ и ждут проверки. Снимите галочку, когда текст утверждён.

Стоимость на карточке берётся из поля «Стоимость». В длинном тексте раздела сумма может быть написана ещё раз — если меняете цену, проверьте и текст.

Якорь раздела `materials` — место, куда встаёт фото материалов внутри раскрытой карточки. У «Таджвид с нуля» там пособия Гулиева.

На сайте две публичные страницы: `/` и `/privacy`. Админка — `/keystatic`. Карта сайта перечисляет только эти две.

## Форма заявки

Поля: имя и фамилия, номер WhatsApp (маска и проверка российского номера), курс из CMS, формат (онлайн / офлайн / пока не определилась), согласие со ссылкой на `/privacy`. Подсказка: «Для записи достаточно номера WhatsApp».

Отправка идёт на `POST /api/lead`: проверка zod, скрытое поле-ловушка, не больше 5 заявок за 10 минут с одного IP (лимит в памяти одного процесса, на нескольких копиях Vercel он не общий).

Дальше два действия. Если переменных нет, шаг пропускается: в лог пишется предупреждение, посетителю показывается успех, чтобы сайт можно было смотреть до выдачи ключей. В dev под успехом есть жёлтая по смыслу приписка в ответе API, её видно на экране. Если ключи заданы и сервис ответил ошибкой, посетителю показывается ошибка и предложение написать в WhatsApp.

Оплаты на сайте нет.

### Google Таблица

Колонки на вкладке `Заявки`:

1. Дата и время заявки (Europe/Moscow), вид `ДД.ММ.ГГГГ ЧЧ:ММ:СС`
2. Имя и фамилия
3. WhatsApp
4. Интересующий курс
5. Формат обучения
6. Статус оплаты, по умолчанию «Не оплачено»

Список статуса: «Не оплачено», «Предоплата 50%», «Оплачено полностью».

Как подключить:

1. Создайте таблицу в Google Sheets. Из адреса `https://docs.google.com/spreadsheets/d/ЭТОТ_ID/edit` скопируйте `GOOGLE_SHEET_ID`.
2. В [Google Cloud Console](https://console.cloud.google.com/) создайте проект.
3. Включите **Google Sheets API** (APIs & Services → Library).
4. APIs & Services → Credentials → Create credentials → Service account. Создайте ключ JSON.
5. Откройте JSON. На Vercel удобно вставить его целиком одной строкой в `GOOGLE_SERVICE_ACCOUNT_JSON`. Либо разложите: `client_email` → `GOOGLE_SERVICE_ACCOUNT_EMAIL`, `private_key` → `GOOGLE_PRIVATE_KEY` (переносы строк как `\n`).
6. В таблице нажмите «Настройки доступа» и выдайте email сервисного аккаунта роль редактора.
7. Локально запишите переменные в `.env.local` и один раз выполните:

```bash
npm run setup-sheet
```

Скрипт создаст вкладку «Заявки», если её нет, запишет строку заголовков, закрепит её и повесит выпадающий список на колонку статуса (строки 2–500). Уже внесённые заявки он не стирает, но первую строку перезаписывает заголовками.

Повторный запуск безопасен: вкладка не дублируется.

Если ученица пишет сразу в WhatsApp, менеджер добавляет её в ту же таблицу руками: имя, номер, курс, дата и статус. Сайт этого шага не делает.

### Telegram

Бот пишет одному пользователю — менеджеру.

1. В Telegram откройте [@BotFather](https://t.me/BotFather), команда `/newbot`, сохраните токен в `TELEGRAM_BOT_TOKEN`.
2. Напишите своему боту любое сообщение (кнопка Start). Без этого бот не сможет писать вам первым.
3. Узнайте chat id:

```bash
curl "https://api.telegram.org/bot<ТОКЕН>/getUpdates"
```

В ответе найдите `"chat":{"id":123456789`. Это `TELEGRAM_CHAT_ID`. Для личного чата id пользователя и id чата совпадают.

4. Перезапустите сервер или пересоберите Vercel.

Сообщение содержит имя, WhatsApp, курс, формат, время по Москве и статус «Не оплачено».

## Деплой на Vercel

Отдельный сервер не нужен: обычный проект Next.js.

1. Импортируйте репозиторий `salmanbahaev/djawda`.
2. Framework Preset: Next.js. Команды по умолчанию: `npm run build`, `next start`.
3. Добавьте переменные из `.env.example`. Для продакшена хранение Keystatic — `github`.
4. Задеплойте. Адрес проекта, если имя `djawda`: `https://djawda.vercel.app`.
5. В GitHub App callback должен совпадать с этим доменом. Если домен другой, поправьте callback и Homepage URL.
6. После первой выкладки один раз выполните `npm run setup-sheet` там, где есть доступ к `.env` с ключом таблицы (со своего компьютера достаточно).

`NEXT_PUBLIC_KEYSTATIC_STORAGE` и `NEXT_PUBLIC_KEYSTATIC_GITHUB_APP_SLUG` читаются на сборке. После их изменения нужен новый деплой.

## Что сознательно не сделано или принято по умолчанию

- Блока отзывов нет.
- У преподавателей нет фотографий.
- Ролик и видео с занятий не встраиваются.
- Фото кабинета не используются.
- Сайт — одна страница. Отдельных адресов `/about`, `/contacts` и `/courses/…` нет.
- Все курсы помечены «Скоро набор», пока статус не сменят в админке.
- Ответы FAQ — черновики в CMS: вопросы из ТЗ, тексты ответов сжаты из тех же разделов, без обещаний результата сверх ТЗ.
- Политика конфиденциальности — заглушка.
- Знак в интерфейсе — PNG. SVG-след лежит рядом и в шапке не используется.
- Карта в контактах — виджет Яндекса без ключа. Координаты дома «ул. Нурсултана Назарбаева, 23А» сверены со страницей дома на Яндекс Картах: 43.332611, 45.685504, масштаб 17. Широта, долгота и масштаб правятся в настройках Keystatic. «Построить маршрут» открывает маршрут Яндекса до этой точки, «Открыть в 2ГИС» — прежнюю ссылку 2ГИС.
- Лимит заявок хранится в памяти процесса.
- Пока нет ключей Google и Telegram, заявка никуда не уходит, но форма отвечает успехом и пишет предупреждение в лог сервера.
